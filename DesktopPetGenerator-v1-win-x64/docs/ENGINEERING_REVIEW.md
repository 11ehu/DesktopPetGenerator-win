# 工程化审查 · 2026-09-19

当前版本已经具备可运行产品的主干：完全本地处理、固定模型版本和 SHA-256、独立推理进程、任务取消、相对资源路径、可搬移宠物包、自动化算法与端到端验收。以下项目按风险和投入排序，不表示当前程序不能使用。

## P0：正式对外发布前

1. **授权合规结论不足**：YOLOv8n-Pose 权重来源仓库标注 AGPL-3.0。正式分发、闭源或商用前，应取得明确授权意见，履行开源义务，或替换为许可更适合产品分发的姿态模型。人物照片的肖像权、素材授权也需要用户确认流程。
2. **没有代码签名和可信安装包**：目前是复制文件夹运行。对陌生用户容易触发 SmartScreen，也不能可靠安装 VC++ 运行库、创建卸载项或校验升级。应制作版本化安装器，并给 EXE、DLL 和安装包签名。
3. **尚无全新系统验收矩阵**：现在只在本机 Windows x64 验证。至少需要 Windows 10/11、100%/150%/200% DPI、单/多显示器、无开发工具的新虚拟机，覆盖“只装 .NET/VC++ 运行库”和中文/英文路径。
4. **崩溃诊断不完整**：有后台日志，但播放器 UI 线程异常仍缺少统一的本地崩溃报告、版本号、操作系统信息和可导出的诊断包。应保证异常不会显示框架级调试窗口，并能让用户一键打开日志位置。

## P1：提高可维护性和发布质量

1. **缺少 `.sln` / `.csproj` 和现代构建系统**：当前依赖系统目录下的 C# 5 编译器及 PowerShell 文件清单，IDE 分析、依赖恢复、资源版本、可重复发布都较弱。建议迁移到 SDK 风格项目（仍可发布 Windows x64），按 Generator、Inference、Player、Shared、Tests 建立项目引用。
2. **没有 CI/CD 和源代码版本库证据**：应在每次提交上自动执行 build、test、无 Python 扫描、真实模型可选验收、依赖/许可证扫描，并产出带版本号和 SHA-256 的发布包。目前真实模型测试依赖本地已有约 1006 MiB 模型。
3. **版本管理不完整**：EXE 没有正式的产品版本、Git 提交号、构建日期和升级兼容策略；`pet.json` / `rig.json` 虽有版本字段，但没有迁移器和兼容测试。应采用语义版本并记录格式升级规则。
4. **依赖恢复仍偏手工**：依赖清单有哈希，但清单本身没有签名；VC++ 运行库只写了前置要求。应使用锁文件/SBOM，生成第三方公告，并在安装时检测或安装正确的 VC++ x64 运行库。
5. **播放器设置不持久化**：跟随、重力、尺寸、动画等右键设置只在本次进程生效。专业应用应区分宠物配置与用户偏好，原子保存且提供“恢复默认”。
6. **可观测性偏弱**：后台采用 JSON 行协议是好的，但没有结构化日志等级、任务 ID、耗时分阶段统计、日志轮转或敏感路径脱敏。生成失败时界面可给出更可执行的建议。

## P2：产品完成度

1. **模型体积和 CPU 时延较大**：三个模型约 1006 MiB，本机 BiRefNet CPU 单图约 52 秒。SCHP 已采用约 66 MiB INT8 权重；后续可评估安全量化 BiRefNet、较小抠图模型和 DirectML 可选执行提供程序，所有优化都要以 alpha IoU、部件覆盖和关节点漂移守住质量。
2. **真人动画仍是二维合成**：现已用 SCHP 人体部件分割与 YOLO 骨段融合，但单照片仍没有被遮住的身体像素。交叉手臂、长裙、宽袖、头发遮挡和大幅转身仍可能露缝。下一步应做遮挡顺序编辑和局部修补，而非继续增大旋转角度。
3. **界面与无障碍不足**：界面为固定 WinForms 布局，尚未系统验证高 DPI、键盘导航、读屏、颜色对比、长文本和多语言。模型首次下载也应明确空间需求、剩余时间、重试和离线导入。
4. **发布能力不足**：缺少自动更新、问题反馈入口、隐私与许可页面、首次使用引导、模型缓存管理和磁盘空间清理。

## 建议迭代顺序

先完成授权决策、干净虚拟机测试、安装器/代码签名和崩溃日志；再迁移现代项目结构与 CI；然后做偏好持久化、下载体验和性能优化；最后投入人体部件分割及遮挡编辑。这样能先降低发布风险，再提高动画上限。
